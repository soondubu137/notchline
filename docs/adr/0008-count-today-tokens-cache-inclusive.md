# 以含缓存的口径统计当日 token，使两个产品的数字可比

面板底部的当日 token 用量对两个产品采用同一口径：全部被处理的输入（含缓存读取）加上输出。Codex 取 `account/usage/read` 的 `dailyUsageBuckets[].tokens`，其口径可由 CLI rollout 的 `token_count` 事件验证——11806 条记录中 `total_tokens = input_tokens + output_tokens` 成立 11679 条，`cached_input_tokens` 从未超过 `input_tokens`，`reasoning_output_tokens` 从未超过 `output_tokens`，即缓存读取被计入输入之内；因此直接读取 `total_tokens`，不重新累加。Claude Code 把同一数量拆开报告，`input_tokens` 只含未命中缓存的输入，`cache_creation_input_tokens` 与 `cache_read_input_tokens` 是并列的加项，对应口径为四者之和。该选择放弃"只算输入加输出"和"输入输出加缓存写入"两种更小的口径：同一天在同一台机器上，三种口径分别为 `4.0M`、`22.6M` 与 `949.2M`，相差 237 倍，而两个产品的数字要并排显示在同一行上，口径不一致等于邀请用户做一次没有意义的比较。对齐后二者约 95% 都是缓存读取，量级一致（2026-08-15 实测 Codex `310.1M`、Claude Code `208.6M`）。仍未实测的一环是服务端 `dailyUsageBuckets.tokens` 是否与 CLI 的 `total_tokens` 同口径：以某一天的 rollout `total_tokens` 求和与该日 bucket 对比即可确认，在确认之前这一数字按推断使用。
