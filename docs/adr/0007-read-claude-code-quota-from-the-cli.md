# Read Claude Code quota from the CLI, not from a Claude Desktop private file

> **Amended by [ADR 0021](0021-read-the-quota-from-the-record-the-command-leaves.md) on 2026-09-09.** This decision stands: the quota comes from the CLI, the Desktop file is still rejected, and reading a credential to call the endpoint directly is still a NO-GO. What moved is the last paragraph below — the numbers are no longer taken out of the `result` string. The same run leaves them in `~/.claude.json` as `cachedUsageUtilization`, as JSON with the fetch's own timestamp, and they are read from there. The command is still run, on the same cadence, because the run is what performs the fetch that writes it. The prose is asked one question only, and the answer is a sentence rather than a number: an answer beginning `Total cost:` is the shape the command takes when the CLI is not signed in, which is a state a Claude Desktop-only machine reaches without anything reporting it.

Claude Code's rolling quota windows are read on demand with `claude -p "/usage" --output-format json`. The call does not reach a model: measured `total_cost_usd` of `0`, `num_turns` of `0` and zero for every token count, taking about `4.3` seconds and writing an approximately `3 KB` transcript each time, without adding to the session count in the user's own usage report. It is therefore a background refresh source and must never be called synchronously when the panel expands.

The rejected alternative was `~/Library/Application Support/Claude/plan-usage-history.json`: private Claude Desktop state that a CLI-only user does not have at all, measured as sparse and sometimes more than a day stale. Reading the CLI makes quota work for every Claude Code user and removes the Desktop dependency entirely.

The cost is that while the outer JSON is stable, the numbers sit inside the natural-language `result` string, so parsing is regex matching against a format nobody guarantees. A parse failure, a command error or a format change must degrade to the full quota-unavailable track — never reuse the previous numbers, never extrapolate. Reading OAuth credentials to call an undocumented endpoint directly is not adopted either; it is the same class as §9's "read a private token and reverse an undocumented channel", already a NO-GO.
