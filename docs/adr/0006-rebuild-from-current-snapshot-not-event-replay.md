# Rebuild from the current snapshot, never by replaying history

At launch, reconnect and correction, Notchline rebuilds the monitored list from two things: the current activity projection that Hooks maintain across the lifecycle, and Desktop's unread terminal state. The one-off event directory is not a replayable state log — an event file written before launch cannot create a row, and a historical `Stop` cannot restore a terminal state. The only lasting effect of `Stop`/`SessionEnd` is to remove the Turn from the current activity projection.

Both alternatives fail in opposite directions: a standalone App Server may report a Thread that Desktop is actively running as `notLoaded`, so relying on `thread/list` alone misreports Idle, while persisting the full reducer restores stale state. The minimal current projection sits between them, keeping only current exact identities and input pairing — never titles, Projects, content or terminal history. On its first upgrade an old helper may fold its unconsumed event queue once, but the output is still only the final active set.
