# Vibe Coding 项目开发流程

## 1. 明确需求

1. 定义产品要解决的问题、目标用户和核心使用场景。
2. 明确 V1 的功能范围与非目标，避免在开发过程中持续扩张范围。
3. 将需求拆分为可独立验证的用户故事。
4. 为每个用户故事补充验收标准、边界条件和异常情况。
5. 定义产品状态及其转换规则，例如空闲、运行中、等待输入、成功和失败。
6. 记录隐私、权限、性能、兼容性和可访问性要求。
7. 将需求整理到 `PRD.md`，并在进入设计前完成评审。

## 2. 制作 UI/UX 原型

1. 根据 PRD 梳理主要用户流程和界面状态。
2. 先制作低保真线框图，验证信息架构、操作路径和内容层级。
3. 制作高保真 Figma 原型，覆盖折叠态、悬停展开态、任务列表和异常状态。
4. 为组件定义尺寸、间距、颜色、字体、圆角、阴影和动画规则。
5. 覆盖不同 Mac 屏幕、刘海尺寸、多显示器和无刘海屏幕的适配方案。
6. 使用可点击原型验证悬停、点击、展开、收起和任务操作流程。
7. 将设计决策、组件状态和交互规则记录到 `figma-design.md`。
8. 根据原型评审结果更新 PRD，保持需求和设计一致。

## 3. 进行技术可行性验证

1. 将高风险技术问题拆成相互独立的最小实验。
2. 验证 macOS 顶部区域窗口的定位、层级、跨 Space 行为和全屏行为。
3. 验证悬停展开面板的动画、鼠标事件、焦点管理和点击外部收起行为。
4. 验证获取 Codex task 状态的数据来源、事件格式、更新延迟和错误处理方式。
5. 验证从任务列表跳转到对应 Codex task 的可行方式。
6. 验证多显示器、显示器切换、分辨率变化和菜单栏自动隐藏场景。
7. 为每个实验记录假设、实现方式、结果、限制和结论。
8. 删除或隔离一次性实验代码，只将验证后的结论带入正式架构。

## 4. 完成系统设计

1. 绘制应用的模块关系和主要数据流。
2. 定义 Codex 状态采集层，负责连接、解析、重连和错误恢复。
3. 定义领域模型，统一表示 task、状态、时间、等待原因和错误信息。
4. 定义状态聚合规则，将多个 task 状态归纳为顶部组件的整体状态。
5. 定义 UI 状态管理方式，区分领域状态、展示状态和瞬时交互状态。
6. 定义窗口管理层，负责位置计算、屏幕变化、展开收起和层级控制。
7. 定义持久化范围，只保存必要的偏好设置和非敏感数据。
8. 定义日志、诊断信息和崩溃排查策略。
9. 定义权限、隐私和本地数据边界。
10. 将架构、接口、关键流程和失败恢复策略写入 `ARCHITECTURE.md`。
11. 使用 ADR 记录影响较大的技术选择及其取舍。

## 5. 初始化工程

1. 创建 macOS 应用工程并确定最低系统版本。
2. 配置 Debug、Release、签名、Bundle Identifier 和应用权限。
3. 建立清晰的源码目录、测试目录、资源目录和文档目录。
4. 配置格式化、静态检查和编译警告策略。
5. 配置单元测试、集成测试和 UI 测试 target。
6. 配置持续集成，至少执行构建、静态检查和自动化测试。
7. 在 `AGENTS.md` 中记录工程结构、构建命令、测试命令、编码约定、约束和完成标准。
8. 保证新环境可以通过文档中的命令完成构建和测试。

## 6. 实现最小垂直切片

1. 选择一条从数据输入到界面输出的最短完整路径。
2. 接入一个可控的模拟 Codex task 数据源。
3. 将输入事件转换为统一的领域状态。
4. 根据领域状态计算顶部组件的整体状态。
5. 在顶部区域显示最小状态指示器。
6. 实现悬停展开并显示一条任务信息。
7. 为状态转换和整体状态计算添加单元测试。
8. 在真实 macOS 环境中验证窗口位置、交互和生命周期。
9. 确认该切片可以独立构建、运行、测试和演示。

## 7. 按功能切片迭代

1. 将剩余需求拆成小型、可独立验收的功能切片。
2. 按风险和用户价值排序，优先处理高风险依赖和核心体验。
3. 每个切片只包含一个清晰结果，避免同时修改无关模块。
4. 先补充或更新测试，再实现最小必要代码。
5. 使用模拟数据验证所有状态，再接入真实数据源。
6. 每完成一个切片，执行构建、测试、静态检查和手动验收。
7. 更新相关 PRD、设计和架构文档。
8. 使用小而完整的 commit 保存通过验收的改动。

## 8. 执行单个 Vibe Coding 任务

1. 为一个 task 定义单一、可验证的目标。
2. 提供相关文件、现有行为、设计稿和必要背景。
3. 明确允许修改的范围、技术约束和禁止事项。
4. 使用可观察结果描述完成条件。
5. 要求先检查现有实现和测试，再提出实现计划。
6. 检查计划是否覆盖异常路径、回归风险和验证方式。
7. 让 Codex 实现改动并同步补充测试与文档。
8. 审阅 diff，重点检查逻辑正确性、边界条件、并发、资源释放和无关改动。
9. 运行对应的自动化测试和手动验收流程。
10. 发现问题时提供具体错误、复现步骤和预期行为，继续在同一 task 中修正。
11. 达到完成标准后再创建 commit。

## 9. 测试与质量加固

1. 为状态解析、状态转换、聚合优先级和排序规则编写单元测试。
2. 为数据源断开、重连、重复事件、乱序事件和未知状态编写集成测试。
3. 为折叠、悬停、展开、收起和任务点击编写 UI 测试。
4. 手动验证有刘海屏幕、无刘海屏幕和不同缩放比例。
5. 手动验证单显示器、多显示器、显示器插拔和主屏切换。
6. 手动验证全屏应用、多个 Space、菜单栏自动隐藏和系统休眠恢复。
7. 验证零任务、单任务、多任务、长标题和大量任务场景。
8. 验证等待 approval、任务成功、任务失败和连接异常场景。
9. 测量空闲 CPU、内存、事件延迟、动画流畅度和长时间运行稳定性。
10. 检查日志中是否包含敏感路径、提示词、凭证或不必要的任务内容。
11. 执行回归测试并记录仍然存在的已知限制。

## 10. 执行完成标准检查

1. 确认实现符合 PRD 的验收标准。
2. 确认界面和交互符合 Figma 设计及状态说明。
3. 确认所有新增逻辑都有适当的自动化测试。
4. 确认构建、静态检查和测试全部通过。
5. 确认关键场景已在真实设备上手动验证。
6. 确认没有未解释的警告、崩溃、明显性能回退或隐私问题。
7. 确认代码、测试、文档和配置保持一致。
8. 确认 diff 不包含调试代码、临时文件或无关改动。
9. 确认 commit 信息能够准确描述改动目的。

## 11. 发布应用

1. 确定版本号和发布说明。
2. 使用 Release 配置执行完整构建和测试。
3. 配置 Developer ID 签名、Hardened Runtime 和必要 entitlements。
4. 完成公证并验证应用可以在干净的 macOS 环境中启动。
5. 验证首次启动、权限提示、登录启动和卸载流程。
6. 打包发布产物并生成校验信息。
7. 准备安装说明、隐私说明、已知限制和问题反馈方式。
8. 先进行小范围测试发布，再根据反馈扩大分发范围。
9. 为发布版本创建 Git tag，并保存可复现的构建记录。

## 12. 复盘与持续迭代

1. 收集崩溃、性能、错误日志和用户反馈。
2. 将反馈区分为缺陷、体验优化、新功能和技术债。
3. 评估每项改动的用户价值、风险、成本和依赖关系。
4. 更新 PRD、设计稿、架构文档和迭代计划。
5. 将重复出现的问题转化为测试、检查规则或工程约束。
6. 删除失效的实验代码、临时兼容逻辑和过期文档。
7. 对每个版本重复需求、设计、验证、实现、测试和发布流程。
