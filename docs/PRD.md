# Codex in Notch — 产品需求文档

| 字段 | 内容 |
| --- | --- |
| 文档状态 | 草案 |
| 版本 | 0.2 |
| 日期 | 2026-08-09 |
| 目标版本 | V1 MVP |
| 目标平台 | 配备物理摄像头刘海的 Mac 内置屏幕 |

## 1. 产品概述

Codex in Notch 是一款轻量级 macOS 工具，利用 Mac 内置显示屏摄像头刘海周围的区域，显示本地 Codex 会话的当前状态。收起时，它以与物理刘海等高、向左右延伸的纯黑组件融入刘海；鼠标悬停时从屏幕上沿向下展开，显示所有相关会话及其当前内容，从而避免使用持续遮挡工作内容的悬浮组件。

第一版聚焦于状态监控与会话导航，不替代 Codex 应用，也不会代替用户批准命令或回答 Codex 的提问。

## 2. 问题描述

Codex 任务经常需要在后台运行数分钟，并可能因等待权限批准或用户输入而暂停。当 Codex 窗口被其他应用覆盖或位于另一个桌面空间时，用户很难快速判断任务仍在执行、已经完成、执行失败，还是正等待人工处理。

现有悬浮状态组件会占用有效屏幕空间，并可能遮挡应用内容。摄像头刘海及其相邻菜单栏区域提供了一个持续可见、干扰较小的位置，适合用于传达 Codex 状态。

## 3. 产品目标

V1 必须实现以下目标：

1. 让用户一眼理解所有本地 Codex 会话的汇总状态。
2. 让等待权限批准或用户输入的状态与普通运行状态有明确区别。
3. 在展开后的列表中显示所有相关会话的标题、状态和当前内容。
4. 让用户可以快速返回相关 Codex 会话。
5. 在 Codex in Notch 或 Codex 重启后恢复有用的会话状态。
6. 保持低干扰、本地优先，并尽量降低 CPU 与电池消耗。
7. 在收起状态中持续显示下次额度重置前剩余的 token 百分比。

## 4. V1 非目标

V1 不包含以下能力：

- 启动、引导、取消、归档或以其他方式管理 Codex 任务。
- 批准终端命令、文件修改、网络访问或其他权限请求。
- 将用户输入、智能体思考或最终回答发送到本机之外，或将这些正文持久化保存。
- 替代 Codex 桌面应用、命令行工具或 IDE 扩展。
- 监控 Codex 以外的智能体。
- 在多台 Mac 之间同步状态。
- 提供插件市场或第三方扩展接口。
- 以 Mac App Store 为首发渠道。初始版本可在签名和公证后直接分发。
- 为无物理刘海的 Mac 或显示器提供 fallback 界面；该方案将在后续版本单独讨论。

## 5. 目标用户

初始目标用户是符合以下特征的开发者：

- 在 macOS 上使用 Codex Desktop 或 Codex CLI。
- 经常同时运行一个或多个耗时较长的任务。
- 工作时通常将 Codex 窗口置于后台或另一个桌面空间。
- 希望以低干扰方式获知 Codex 何时需要人工处理。

## 6. 核心用户故事

1. 作为用户，我可以看一眼摄像头刘海区域，就知道 Codex 当前是空闲、运行中、等待中、已完成还是失败。
2. 作为用户，我可以区分“需要我的输入”和“仍在自动执行”的任务。
3. 作为用户，我可以将鼠标悬停在刘海组件上，查看所有相关会话的标题、状态与当前内容。
4. 作为用户，我可以点击某个会话并返回 Codex 中对应的会话页面。
5. 作为用户，我可以重启菜单栏应用，而不会丢失活动任务的状态。
6. 作为用户，我可以在不展开组件的情况下查看下次额度重置前剩余的 token 百分比。

## 7. V1 功能范围

### 7.1 首次启动与集成设置

- 检测本机是否存在兼容的 Codex 安装和 Codex 主目录。
- 说明应用会读取哪些本地 Codex 元数据，以及读取这些数据的原因。
- 仅在用户确认后安装或注册用户级 Codex 生命周期钩子。
- 检测无效、缺失、已禁用或尚未信任的钩子配置，并提供修复指引。
- 提供“登录时启动 Codex in Notch”选项。
- 当 Codex 集成不可用时，显示明确的“连接已断开”状态。

### 7.2 本地任务状态采集

- 监听本地 Codex Desktop 和 Codex CLI 的任务生命周期事件。
- 支持同时运行多个活动任务。
- 将 Codex 事件归一化为以下产品状态：
  - 空闲
  - 运行中
  - 等待批准
  - 等待输入
  - 已完成
  - 失败
  - 已取消
  - 未知或连接已断开
- 应用重启后，从本地 Codex 会话元数据中恢复任务状态。
- 为展开视图读取每个相关会话最新的当前内容；内容可以是用户输入、智能体思考或最终回答。
- 获取下次额度重置前剩余的 token 百分比，并在无法可靠获取时显示明确的不可用状态，不得伪造估算值。
- 对重复事件进行去重，并忽略乱序到达的过期事件。
- 所有事件处理均在本机完成，并采用事件驱动方式，避免持续进行高频轮询。

### 7.3 紧凑刘海状态指示器

- 仅在带物理摄像头刘海的 Mac 内置屏幕顶部中央显示组件。
- 收起状态的可见高度必须与当前设备的物理刘海高度完全一致，并保持吸附于屏幕上沿。
- 组件从物理刘海左右两侧各水平延伸一段距离，整体使用纯黑背景，使其视觉上成为横向拉长的刘海。
- 组件与桌面相接的外侧底角弧度必须匹配当前设备物理刘海的对应边角弧度；不得以一组固定圆角近似所有机型。
- 左侧延伸区仅显示汇总状态提示；右侧延伸区显示下次额度重置前剩余的 token 百分比，使用白色文字。
- 为重要汇总状态提供不同的颜色与动态效果：
  - 空闲：中性灰色，无动画。
  - 运行中：蓝色或白色脉冲动画。
  - 等待批准或输入：琥珀色提醒动画。
  - 已完成：短暂显示绿色确认状态。
  - 失败：红色错误状态。
  - 连接已断开：弱化轮廓或警告标记。
- 遵循 macOS 的“减少动态效果”系统设置。
- 被动更新状态时，不激活应用，也不抢占键盘焦点。

### 7.4 汇总状态规则

当多个任务处于不同状态时，紧凑指示器按照以下优先级显示汇总状态：

1. 等待批准或输入
2. 运行中
3. 最近失败
4. 最近完成
5. 空闲

如果部分任务仍在运行，同时另一个任务刚刚失败或完成，指示器可以使用次级徽标提示结果，同时保留更高优先级的活动状态。

当不存在活动任务时，已完成和失败状态保留一小段时间，随后自动恢复为空闲状态。

### 7.5 悬停展开会话列表

- 鼠标进入刘海或其左右延伸区并有意悬停一小段时间后，组件从收起轮廓向下拉伸展开。
- 展开过程中组件始终吸附于屏幕上沿，不得整体下移，也不得变成与刘海分离的浮动卡片。
- 展开轮廓继续使用纯黑背景；与桌面相接的外侧底角弧度必须继续匹配物理刘海的边角弧度。
- 鼠标离开后延迟收起，以避免界面闪烁。
- 展开区域显示所有相关 Codex 会话，而不只显示当前正在运行的会话。
- 每个会话仅显示以下信息：
  - 会话标题
  - 当前状态
  - 当前内容；可以是最新用户输入、智能体思考或最终回答
- 当前版本不得在会话行中显示项目或工作目录、时长、等待原因、token 用量、时间戳或其他辅助信息。
- 当前内容使用适合快速浏览的预览；超出单个会话行可用空间时截断，不在面板内展开完整正文。
- 按照需要人工处理的优先级排序；优先级相同时，最近更新的会话排在前面。
- 通过文字和视觉样式区分活动、等待、完成、失败和取消状态。
- 当会话数量超过可用高度时，保持面板紧凑并允许滚动。
- 用户可以按 Escape 键关闭展开面板。

### 7.6 在 Codex 中打开会话

- 每个会话行均可点击。
- 当 Codex 支持稳定的会话深层链接时，打开并聚焦相应会话。
- 如果无法直接导航到会话，则打开 Codex，并提供清晰的导航 fallback，同时保留用户选择的会话上下文。
- 打开会话不得修改会话状态，也不得向会话发送新输入。

### 7.7 带刘海内置屏幕的几何适配

- 使用公开的 macOS 屏幕几何和安全区域接口，确认内置屏幕存在物理摄像头刘海，并推导该设备的刘海高度、宽度与边角几何。
- 组件只锚定到带刘海的内置屏幕，不在无刘海外接显示器上复制显示。
- 当分辨率、缩放、菜单栏自动隐藏或全屏状态变化时，重新计算组件位置和命中区域，同时保持其吸附于屏幕上沿。
- 无刘海设备与无刘海显示器的 fallback 行为不属于当前版本范围，后续单独定义。

### 7.8 设置与控制

V1 设置必须包含：

- 登录时启动。
- 启用或禁用状态动画。
- 重新运行或修复 Codex 集成设置。
- 退出 Codex in Notch。

### 7.9 隐私与安全

- 所有 Codex 状态数据均在本机处理。
- 仅持久化必要的会话元数据：会话标识符、标题、状态和时间戳。
- 用户输入、智能体思考和最终回答仅在本机按需读取并用于当前界面展示，默认不写入 Codex in Notch 的持久化存储。
- 不向本机之外传输会话内容；不读取或保存文件差异、源代码、凭据或与界面展示无关的命令输出。
- 任务监控过程不发起网络请求。
- 核心 V1 功能不申请“辅助功能”或“屏幕录制”权限。
- 权限批准信息仅用于显示；应用不能授予权限。
- 在修改任何用户级 Codex 钩子或配置前，明确告知用户将要进行的更改。

## 8. 状态模型

| 产品状态 | 含义 | 左侧状态提示 | 退出条件 |
| --- | --- | --- | --- |
| 空闲 | 没有活动或等待中的任务 | 灰色、静态 | 新任务开始 |
| 运行中 | 至少一个任务正在处理 | 蓝色或白色脉冲 | 任务开始等待、完成、失败或被取消 |
| 等待批准 | Codex 需要用户作出权限决定 | 琥珀色提醒状态 | 请求被处理或任务结束 |
| 等待输入 | Codex 需要用户回复 | 带输入标识的琥珀色提醒状态 | 用户回复或任务结束 |
| 已完成 | 任务成功完成 | 绿色确认状态 | 保留时间结束或新任务开始 |
| 失败 | 任务因错误而结束 | 红色错误状态 | 用户查看、保留时间结束或出现更高优先级状态 |
| 已取消 | 任务被中断或取消 | 中性取消标记 | 保留时间结束 |
| 连接已断开 | Codex 集成不可用或状态不可靠 | 弱化警告状态 | 集成重新连接 |

右侧 token 余额不随汇总状态改变位置，始终以白色百分比文字显示下次额度重置前的剩余额度；数据不可用时显示 `—`。

## 10. 非功能需求

### 10.1 性能

- 正常本地环境下，状态变化应在相应 Codex 事件发生后的一秒内显示。
- 动画运行时，收起界面应保持 60 帧每秒的响应能力。
- 空闲 CPU 占用应接近于零，不得频繁扫描整个会话目录。
- V1 稳态内存占用目标低于 100 MB。

### 10.2 可靠性

- 格式错误或未知的 Codex 事件不得导致应用崩溃。
- 事件连接丢失时，必须显示“连接已断开”，而不是错误地显示为空闲。
- 重复事件不得创建重复任务。
- 应用或 Codex 重启后，必须重新校正过期任务状态。

### 10.3 无障碍

- 不得仅通过颜色传达状态。
- 展开面板必须为会话标题、状态和当前内容预览提供有意义的旁白标签。
- 当系统启用“减少动态效果”时，必须减少或禁用动画。

## 11. V1 验收标准

满足以下全部条件时，V1 可以发布：

1. 正常本地环境下，启动 Codex 任务后，指示器在一秒内从空闲变为运行中。
2. 出现权限批准请求时，相应任务变为等待批准，汇总指示器提升为提醒状态。
3. 展开列表能够区分用户输入请求与权限批准请求，并为每个相关会话显示标题、状态和当前内容预览。
4. 等待状态被处理后，无需手动刷新，任务自动恢复为运行中或进入最终状态。
5. 成功完成和执行失败均能正确显示；最终回答可以作为对应会话的当前内容预览。
6. 至少三个并发会话可以被独立表示，并同时显示在列表中。
7. 活动任务运行期间重启 Codex in Notch 后，应用能够重建有用状态，且不会错误地显示为成功完成。
8. 收起组件与测试设备的物理刘海等高、背景纯黑、左右延伸且边角匹配；左侧显示状态，右侧以白字显示 token 剩余百分比。
9. 鼠标悬停可以使组件从屏幕上沿向下展开且不激活应用；鼠标离开后自动收起，整个过程不脱离屏幕上沿，展开边角继续匹配物理刘海。
10. 点击会话能够打开 Codex；当已安装的 Codex 版本支持时，可以直接聚焦对应会话。
11. 展开会话行不显示项目、工作目录、时长、等待原因、时间戳或其他未列出的信息。
12. Codex in Notch 不持久化用户输入、智能体思考、最终回答、源代码、文件差异或凭据。
13. 在连续观察三十分钟后，空闲资源占用符合性能目标。

## 12. 技术假设与约束

- 标准 macOS 状态项目无法可靠地放置在菜单栏中央，因此刘海界面将使用无边框、非激活的 AppKit 面板承载 SwiftUI 内容。
- 物理摄像头刘海区域没有显示像素，因此收起状态的状态提示和 token 余额必须分别落在刘海左右两侧的可显示延伸区。
- 不同带刘海 Mac 机型和显示缩放可能产生不同的安全区域几何；组件高度、左右起点和圆角必须由实际屏幕几何推导，并通过原生原型逐机验证。
- 单独启动的 Codex app-server 可以读取已保存的任务历史，但不一定能够共享另一个 Codex Desktop 进程所拥有任务的实时状态。
- 因此，V1 将以用户级生命周期钩子作为主要事件来源，以本地会话元数据作为状态恢复与兼容性来源。
- 钩子会同步执行，因此钩子辅助程序必须只发送最小本地事件并立即退出，不能阻塞 Codex。
- Codex 事件和会话格式可能演进；事件解析必须隔离在可进行版本管理的适配器后面。

## 13. 交付计划

### 13.1 里程碑 0：集成验证

- 验证 Codex Desktop 和 Codex CLI 的生命周期钩子行为。
- 验证权限批准和用户输入事件的完整顺序。
- 验证从本地会话元数据恢复任务状态的可行性。
- 确认任务深层链接行为。
- 验证不同带刘海内置屏幕、显示缩放、全屏模式和自动隐藏菜单栏情况下的刘海几何与顶部吸附。
- 验证 token 剩余百分比及下次额度重置信息的可靠、最小权限数据来源，优先复用 Codex 已有本地状态。
- 验证用户输入、智能体思考和最终回答三类当前内容的实时读取与非持久化展示。

### 13.2 里程碑 1：功能 MVP

- 实现状态归并器和本地事件桥接层。
- 实现紧凑指示器和悬停展开会话列表。
- 支持并发任务、等待状态、完成、失败和重启恢复。
- 添加首次启动集成设置；无刘海 fallback 不纳入本里程碑。

### 13.3 里程碑 2：V1 完善

- 添加设置、登录时启动、无障碍和带刘海内置屏幕适配。
- 添加事件版本兼容性检查和断开连接诊断。
- 测量空闲 CPU、内存、动画性能和状态恢复可靠性。
- 对发布版本进行签名和公证。

## 14. 集成验证阶段待解决问题

1. 当前 Codex Desktop 的所有任务类型是否都会触发所需的用户级生命周期钩子？
2. 判断权限批准或用户输入等待已经解决的最可靠信号是什么？
3. 已安装的 Codex 版本能否通过任务标识符直接深层链接到对应任务？
4. 子智能体任务应显示为独立行，还是嵌套在父任务下？
5. 当全屏应用隐藏菜单栏时，顶部吸附组件应该如何表现？
6. 如何从当前 Codex 版本可靠获取“下次额度重置前剩余百分比”，以及数据不可用时如何恢复？
7. 各带刘海 Mac 机型的实际刘海边角几何能否由公开接口充分推导，还是需要维护经过验证的机型参数？

## 15. 后续版本考虑

V1 之后可以考虑无刘海 Mac 与外接显示器的 fallback、系统原生通知、可选提示音、父子任务分组、主题自定义、任务取消，以及在具备官方安全协议的前提下执行权限批准操作。如果 Codex 未来为现有 Desktop 任务提供受支持的观察者连接，还可以增加直接共享 app-server 的集成方式。
