## 2. 设计中

当前仅设计带物理摄像头刘海的 Mac 内置屏幕体验。本部分记录的是已明确方向但尚未完成最终设计与评审的内容，因此仍归类为“设计中”。

### 2.1 设计范围

本轮只设计以下核心体验：

1. 与物理刘海融为一体的收起状态。
2. 鼠标悬停后从屏幕上沿向下拉伸的展开状态。
3. 收起状态中的汇总状态提示与 token 剩余百分比。
4. 展开状态中的相关会话列表。
5. 带刘海组件的状态变化、动效、内容密度、无障碍和原型流程。

无刘海 Mac、无刘海外接显示器及其 fallback 不属于本轮设计范围。

### 2.2 设计原则

#### 一眼可读

用户不需要展开组件，就能区分空闲、运行中、等待处理、已完成、失败和连接断开。

#### 低干扰

收起状态与物理刘海等高并只向左右延伸，不向下侵入额外工作区域。运行中动画保持平静；只有需要用户处理的状态使用更明显的提醒。

#### 与物理刘海融合

组件应像物理刘海被横向拉长，并在悬停时从同一轮廓向下生长，而不是网页卡片或独立悬浮窗。

#### 状态优先于装饰

动画、颜色和形变只服务于状态传达。当前版本不采用拟人化、宠物化或复杂装饰效果。

#### 不只依赖颜色

等待、失败、完成等状态必须同时通过图标、文字、动画节奏或轮廓差异表达。

#### 渐进披露

收起状态只显示左侧汇总状态与右侧 token 剩余百分比；展开后，每个相关会话只显示标题、状态和当前内容预览。

### 2.3 Figma 页面结构

带刘海部分使用以下页面：

```text
00 — Cover & Notes
01 — Notch Foundations
02 — Notch Components
03 — Compact Notch States
04 — Expanded Session Panel
05 — Notch Interaction Flows
06 — Notch Edge Cases
07 — Notch Prototype
99 — Archive
```

- `00 — Cover & Notes`：版本、更新时间、评审结论和待定项。
- `01 — Notch Foundations`：字体、颜色、间距、刘海几何、圆角和动画参数。
- `02 — Notch Components`：所有带刘海相关的可复用组件及其变体。
- `03 — Compact Notch States`：收起状态矩阵。
- `04 — Expanded Session Panel`：展开面板、会话数量和内容密度。
- `05 — Notch Interaction Flows`：收起、展开、状态变化和会话导航流程。
- `06 — Notch Edge Cases`：长文本、多会话、异常状态和不同带刘海参考几何。
- `07 — Notch Prototype`：用于演示与测试的原型入口。
- `99 — Archive`：被淘汰但需要保留的探索方案。

Onboarding、Settings 和无刘海 fallback 页面暂不进入当前 Figma 主结构，待讨论后再加入。

### 2.4 画板与物理刘海模型

- 使用 `1512 × 982` 作为第一张带刘海内置屏幕的基准逻辑画板。
- 至少在浅色和深色桌面背景上各验证一次核心状态。
- 画板必须包含菜单栏、物理刘海和足够的桌面内容，以判断遮挡程度。
- 物理刘海作为不可显示内容的黑色实体区域处理。
- 不得把文字、图标或其他必要信息放在物理刘海内部。
- Figma 中保留可切换的安全区域、可显示区域和鼠标命中区域标注；这些标注不进入最终原型。

#### 收起几何

- 组件必须与参考设备的物理刘海高度完全一致，并紧贴屏幕上沿。
- 组件从物理刘海左右两侧水平延伸。
- 左侧延伸区放置汇总状态，右侧延伸区放置 token 剩余百分比。
- 组件背景必须为纯黑，并与物理刘海无可见接缝。
- 与桌面相接的两个外侧底角必须匹配参考设备物理刘海的对应边角弧度。
- 不得用同一组固定高度和圆角近似所有带刘海 Mac。

#### 初始探索范围

| 元素 | 当前要求或探索范围 |
| --- | --- |
| 收起组件高度 | 与参考设备物理刘海高度完全一致 |
| 单侧水平延伸宽度 | 以完整容纳左侧状态或右侧百分比为下限，比较紧凑与宽松两档 |
| 展开面板宽度 | 约 360–420 |
| 展开面板最大高度 | 约 420–520 |
| 单行会话高度 | 约 52–68 |
| 外侧底角 | 与参考设备物理刘海边角弧度完全一致 |
| 面板内边距 | 约 12–16 |

紧凑与舒展两种会话密度不得改变收起高度、纯黑背景或刘海匹配圆角。

### 2.5 视觉基础

#### 字体

- 主要字体使用 SF Pro。
- token 百分比等短数字可以探索 SF Mono。
- 会话标题不得小于常规 macOS 菜单与浮层中可舒适阅读的尺寸。
- 文字层级只覆盖会话标题、状态标签和当前内容预览。

#### 图标

- 优先使用 SF Symbols。
- 每种重要状态必须有可识别的图标或轮廓差异。
- 图标保持简洁，不使用品牌化插画或拟人角色。

#### 颜色

建议建立以下语义变量：

```text
surface/notch
surface/session-hover
text/primary
text/secondary
status/idle
status/running
status/waiting
status/completed
status/failed
status/cancelled
status/disconnected
```

- `surface/notch` 固定为纯黑色，不随浅色或深色桌面模式变化。
- 右侧 token 百分比固定使用白色文字。
- 空闲使用中性灰；运行中使用蓝色或冷白色；等待使用琥珀色；完成使用绿色；失败使用红色；取消使用中性灰蓝；断开连接使用弱化灰色和警告标记。
- 所有状态颜色必须在浅色、深色和高对比桌面背景上验证。

#### 材质与层级

- 收起与展开轮廓均使用纯黑实色，不使用近黑、透明材质或背景模糊代替。
- 展开状态必须与屏幕上沿和物理刘海保持连续轮廓。
- 可以使用轻量阴影帮助展开区域与深色桌面分离，但不得形成独立浮动卡片的视觉。
- 避免厚重卡片、明显描边和过度渐变。

#### 间距

- 使用 4 点基础网格。
- 常用间距优先采用 4、8、12、16、20、24。
- 会话行内的状态、标题和当前内容必须稳定对齐。

#### `Notch / Compact`

属性至少包含：

- 汇总状态。
- token 剩余百分比与不可用状态。
- 参考刘海高度与边角几何。
- 浅色或深色桌面环境。
- 正常动态或减少动态。

固定结构为：左侧状态、中间物理刘海、右侧白色 token 百分比；三者共同形成等高、纯黑、贴顶的连续轮廓。

#### `Notch / Expanded`

属性至少包含：

- 会话数量。
- 是否包含等待会话。
- 是否需要滚动。
- 连接正常或断开。
- 参考刘海高度与边角几何。

#### `Status Indicator`

必须包含空闲、运行中、等待批准、等待输入、已完成、失败、已取消和连接断开八种变体。

#### `Session Row`

属性至少包含：

- 会话状态。
- 当前内容类型：用户输入、智能体思考或最终回答。
- 当前内容正常、超长或暂不可用。
- 标题正常或超长。
- 默认、悬停和按下状态。
- 活动会话或已结束会话。

#### 其他组件

- `Empty State`
- `Disconnected State`
- `Current Content Preview`
- `Token Balance`
- `Scrollable Session List`

### 2.7 收起状态

所有收起变体都必须与参考物理刘海等高、使用纯黑背景、贴合屏幕上沿、匹配物理刘海边角，并保持左侧状态与右侧白色 token 百分比的固定结构。

| 状态 | 必须表达的信息 | 动画方向 |
| --- | --- | --- |
| 空闲 | Codex 当前没有活动会话 | 静态 |
| 单会话运行 | 一个会话正在执行 | 低频脉冲或流动 |
| 多会话运行 | 多个会话正在执行 | 低频脉冲 |
| 等待批准 | 至少一个会话需要权限决定 | 明显但不刺眼的琥珀色提醒 |
| 等待输入 | 至少一个会话需要用户回复 | 与批准相近，但图标或节奏不同 |
| 已完成 | 最近一个会话成功完成 | 一次短暂绿色确认动画 |
| 失败 | 最近一个会话执行失败 | 红色错误提示，避免持续快速闪烁 |
| 连接断开 | 当前状态不可可靠获取 | 弱化显示并带警告标记 |

- 左侧状态提示不得侵入物理刘海区域。
- 右侧使用白色文字显示 `NN%`，含义固定为“下次额度重置前剩余的百分比”。
- token 余额不可用时暂用 `—`，不得显示未经验证的估算值；最终不可用样式仍待讨论。
- 本轮不探索状态位于刘海下方或与刘海分离的方向。

### 2.8 展开状态

#### 轮廓与顶部吸附

- 鼠标悬停后，组件从收起轮廓向下拉伸，顶部边缘始终与屏幕上沿重合。
- 展开区域与物理刘海、左右延伸区保持连续的纯黑轮廓。
- 不得出现独立卡片、顶部间隙或透明材质。
- 展开后的外侧底角继续匹配参考设备物理刘海的边角弧度。
- 内容在轮廓获得足够高度后淡入，不得穿过物理刘海的不可显示区域。
- 当前版本不设置面板标题栏，不在会话列表上方额外显示产品名称、会话总数、整体状态或设置入口。

#### 会话行内容

每个相关会话只显示：

1. 会话标题。
2. 当前状态。
3. 当前内容预览。

当前内容可以是：

- 用户的最新输入。
- 智能体当前思考。
- 智能体最终回答。

会话行不得显示：

- 项目或工作目录。
- 已运行、已等待或完成时间。
- 等待原因。
- token 用量或额度重置时间。
- 时间戳、模型名称或其他辅助信息。
- 完整长正文；超出预览空间的内容必须截断。
- 完整命令、文件差异、代码、凭据或敏感路径。

#### 排序

1. 等待批准。
2. 等待输入。
3. 运行中。
4. 最近失败。
5. 最近完成。
6. 最近取消。

同一优先级内，最近更新的会话排在前面。

#### 会话数量场景

- 无相关会话。
- 一个运行中会话，当前内容为智能体思考。
- 三个混合状态会话，分别展示用户输入、智能体思考和最终回答。
- 一个等待会话加多个运行中会话。
- 十个以上相关会话，需要滚动。
- 只有已完成或失败会话。
- 连接断开，会话状态与当前内容不可确认。

### 2.9 关键交互与动效

#### 悬停展开与收起

第一轮原型使用以下可调参数：

- 鼠标进入物理刘海对应区域或左右延伸区后约 `150 ms` 开始展开。
- 展开动画约 `180–220 ms`。
- 鼠标离开后约 `250 ms` 开始收起。
- 鼠标从收起区域移动到展开区域时不得意外收起。
- 按 Escape 立即收起。

这些参数必须在原生 SwiftUI/AppKit 原型中复测。

#### 展开动画

- 面板从刘海区域自然向下展开，顶部始终锁定在屏幕上沿。
- 优先探索宽度和高度同时变化的形变。
- 展开前后保持纯黑连续轮廓和刘海匹配圆角。
- 文字可以略晚于面板轮廓淡入。
- 收起时执行相反顺序。
- 减少动态模式下使用短暂淡入淡出，不使用明显缩放或弹簧动画。

#### 会话行交互

- 悬停会话行时显示轻量背景反馈。
- 点击会话行模拟打开对应 Codex 会话。
- 原型使用过渡页或注释表示“切换到 Codex”，不设计会话编辑行为。
- 等待批准的会话行可以更突出，但不得提供“批准”按钮。

#### 状态动效

- 运行中动画可持续，但必须安静。
- 等待动画可以更明显，但不能快速闪烁。
- 完成动画只播放一次。
- 失败状态可以保留，但错误动画只播放一次。
- 避免幅度过大的弹跳或娱乐化动效。
- 必须提供减少动态版本。

### 2.10 当前原型流程

#### 单会话正常完成

```text
空闲
→ 会话开始
→ 收起状态显示运行中
→ 悬停查看会话标题、状态和当前内容
→ 会话完成
→ 短暂绿色确认
→ 空闲
```

#### 等待人工处理

```text
运行中
→ 等待批准或输入
→ 收起状态提升提醒级别
→ 展开查看对应会话的状态与当前内容
→ 点击会话
→ 模拟打开 Codex
```

#### 多会话

```text
三个会话同时活动
→ 收起状态保持左侧汇总状态与右侧 token 余额
→ 展开面板
→ 等待会话置顶
→ 运行中会话随后
→ 已完成会话位于下方
```

#### 状态链

```text
空闲
→ 运行中
→ 等待批准
→ 运行中
→ 已完成
→ 空闲
```

异常状态链暂用以下流程验证视觉状态；恢复策略仍待讨论：

```text
运行中
→ 连接断开
→ 重新连接
→ 运行中或失败
```

### 2.11 内容与示例数据

原型只使用虚构会话数据，不使用真实用户输入、智能体思考或最终回答。

| 会话标题 | 状态 | 当前内容类型 | 当前内容预览 |
| --- | --- | --- | --- |
| 实现 Codex 状态事件适配器 | 运行中 | 智能体思考 | 正在核对事件顺序与状态映射…… |
| 验证 macOS 刘海窗口定位 | 等待批准 | 智能体思考 | 需要在本机运行窗口定位测试。 |
| 修复会话列表滚动问题 | 等待输入 | 用户输入 | 请优先保证键盘和触控板滚动体验。 |
| 更新产品需求文档 | 已完成 | 最终回答 | 已更新收起与展开状态的产品要求。 |
| 运行全屏集成测试 | 失败 | 最终回答 | 测试未通过，窗口在切换空间后丢失锚点。 |

文案要求：

- 会话标题优先使用动词开头，便于快速扫描。
- 当前内容预览保持紧凑，超出可用行数时尾部截断。
- 预览不得包含完整命令、代码、文件差异、凭据或敏感路径。
- 缺失标题时使用“未命名 Codex 会话”。
- 当前内容暂不可用时显示简短占位文案，不补充项目、时间或其他信息。

### 2.12 边缘场景与无障碍

带刘海部分必须覆盖：

- 超长或缺失的会话标题。
- 超长或暂不可用的当前内容。
- 一个、三个和十个以上会话。
- 多个会话同时等待处理。
- 会话状态快速连续变化。
- 应用刚启动但状态仍在恢复。
- 连接断开后存在过期会话。
- 浅色、深色和高对比桌面背景。
- 减少动态效果。
- 至少两种带物理刘海的内置屏幕参考几何。

无障碍要求：

- 每个状态同时具有颜色以外的图标、轮廓或文字差异。
- 正文和辅助文字与纯黑背景保持足够对比度。
- 会话行命中区域不得过小。
- 等待批准和等待输入必须能够被文字区分。
- 减少动态版本不得依赖动画传达状态。
- 检查红绿色觉差异下的完成与失败状态。
- 原型注释中为核心组件提供建议的旁白标签。

旁白标签示例：

```text
Codex，三个相关会话，其中一个等待批准，token 余额百分之四十二
验证 macOS 刘海窗口定位，等待批准，当前内容：需要在本机运行窗口定位测试
更新产品需求文档，已完成，当前内容：已更新收起与展开状态的产品要求
```

### 2.13 “设计中”完成条件

以下条件全部满足并通过评审后，带刘海部分才能从“设计中”移入“已设计”：

1. 完成空闲、运行、等待批准、等待输入、完成、失败、取消和连接断开八种收起状态。
2. 所有收起状态均与参考物理刘海等高、纯黑、贴顶且边角匹配。
3. 左侧状态和右侧白色 token 百分比在所有收起状态中保持稳定。
4. 完成一个、三个和十个以上会话的展开面板。
5. 展开组件始终吸附屏幕上沿，并保持纯黑连续轮廓和刘海匹配圆角。
6. 每个相关会话只显示标题、状态和当前内容预览，并覆盖用户输入、智能体思考和最终回答三类内容。
7. 等待会话按照产品优先级置顶。
8. 完成单会话、多会话和等待人工处理三条原型流程。
9. 完成浅色、深色和高对比桌面背景验证。
10. 完成正常动画和减少动态版本。
11. 点击会话只模拟打开 Codex，不提供批准或编辑操作。
12. 所有核心元素均由可复用组件和语义变量构成。
13. 核心尺寸、间距、颜色、字体和动画意图均有开发标注。
14. 至少在两组带刘海设备参考几何上完成原生原型验证。

### 2.14 当前设计任务

1. 在不改变刘海等高、纯黑、左右信息分区和匹配圆角的前提下，比较两种左右延伸宽度。
2. 为展开面板制作紧凑版和舒展版两种信息密度；两者都只显示标题、状态和当前内容。
3. 验证从收起轮廓向下拉伸、始终贴顶并保持刘海匹配圆角的形变过程。
4. 制作单会话、多会话和等待人工处理原型。
5. 补齐八种收起状态、异常内容、滚动和减少动态变体。
6. 在至少两组带刘海设备参考几何上验证高度、圆角、命中区域和内容避让。

## 3. 待讨论

以下内容尚未完成设计，不代表已经选定的产品或视觉方案。

### 3.1 首次启动与集成设置

需要讨论是否以及如何设计以下画面：

1. 欢迎与产品价值说明。
2. 本地数据与隐私说明。
3. Codex 安装和主目录检查。
4. 请求用户确认安装生命周期钩子。
5. 等待用户在 Codex 中信任钩子的说明。
6. 集成成功。
7. 集成失败或部分可用。
8. 修复和重新检测入口。

讨论时必须考虑：

- 如何准确说明应用在本机读取会话状态、标题和最新当前内容。
- 如何说明当前内容不会被 Codex in Notch 持久化或发送到本机之外。
- 如何说明应用不能替用户批准 Codex 权限请求。
- 是否允许跳过设置，以及跳过后如何表达连接断开状态。
- 集成失败时提供什么下一步操作。

### 3.2 设置界面

以下内容尚未设计：

- 登录时启动。
- 启用或禁用状态动画。
- Codex 集成状态。
- 重新检测或修复集成。
- 关于和版本信息。
- 退出应用。

需要讨论设置入口与承载方式，例如独立 macOS 设置窗口、标准菜单栏菜单，或其他不占用展开会话区域的方案。

### 3.3 无刘海 fallback

无刘海 Mac、无刘海外接显示器及其 fallback 设计全部留待后续讨论。当前文档不规定其位置、形态、交互或功能范围。

### 3.4 原生平台行为

以下内容不能仅依赖 Figma，需要先讨论再通过 SwiftUI/AppKit 原型验证：

- 如何从实际屏幕几何推导不同机型的刘海高度、宽度与边角。
- 菜单栏自动隐藏时组件如何表现。
- 全屏应用中组件保持显示、按需显示还是隐藏。
- 窗口层级、鼠标命中区域和焦点行为。
- 显示缩放、桌面空间切换和屏幕配置变化后的重新定位。
- 内置带刘海屏幕与外接显示器同时存在时的归属规则。

### 3.5 数据与内容边界

需要讨论：

1. “所有相关会话”的准确范围。
2. 已完成、失败和取消会话保留多久。
3. token 剩余百分比及下次额度重置信息的可靠数据来源。
4. token 余额不可用、正在刷新或即将重置时的文案和视觉状态。
5. 当前内容暂不可用、状态过期或连接断开时显示什么。
6. 用户输入、智能体思考和最终回答的读取边界、刷新策略和本地非持久化保证。

### 3.6 尚未定案的视觉与交互参数

需要讨论并通过 Figma 或原生原型比较：

1. 左右延伸区的最小宽度。
2. 等待批准和等待输入使用不同颜色，还是相同颜色配不同图标。
3. 展开面板的最终宽度、会话行高度和当前内容预览行数。
4. 鼠标离开后的收起延迟。
5. 是否支持点击后固定展开面板。
6. token 余额不可用状态是否继续使用 `—`。
7. 不同带刘海机型的几何参数如何在 Figma 变量和开发标注中维护。
